# v0.1.6：修复点击更新插件后安装失败

在 DSH 插件管理器中升级至 **0.1.6**，包名为 `dsh-apophiscode-api`。

- 修复 Windows 下能够发现新版、点击「更新插件」却因安装程序无法启动而失败的问题。
- 自动处理 Windows、Linux、macOS 的安装程序启动方式，保留桌面宿主自带的 pnpm；
  普通用户继续使用同一个「更新插件」按钮，无需配置安装路径或执行终端命令。
- 更新失败时区分连接失败、超时、权限不足和空间不足，保留重试按钮；
  原始安装输出、路径和凭据不会进入提示。
- 安装结束后核对实际落盘版本，避免把未安装成功显示为更新完成；
  保留宿主发布冷却期、本地文件与开发链接保护。
- 包含 0.1.5 的切换 Key 后模型列表刷新修复。

**从 0.1.4 或 0.1.5 首次取得本修复，请使用 DSH 自带的「设置 → 插件」页面，
安装 `dsh-apophiscode-api@0.1.6`。**旧版插件内的更新器有缺陷，重复点击旧按钮不能取得修复。
安装后完全退出并重新打开原来的 DSH，在 **设置 → ApophisCode → 插件版本**
确认显示 **0.1.6**。如果提示发布冷却期，按提示等待后再试。

Windows 本机与 Ubuntu CI 完整离线检查 **605/605** 通过；原生 Windows、Linux、macOS
的更新进程检查各 **11/11** 通过。运行证据与真实 DSH 验收边界见
[验证记录](https://github.com/ApophisCode/dsh-apophiscode-api/blob/main/docs/validation.md)。
本次没有替使用者安装或重启 DSH，也没有读取用户 Key 或调用真实模型网关。
